## Version 0.3.0: Explicit-Invocation Policy Locked

**Date:** 2026-03-30
**Status:** Recorded

### Added

- Recorded the final current operator policy for `nodejs-backend-expert`

### Findings

- repeated validation did not show reliable explicit specialist delegation for broad architecture-heavy backend prompts
- domain-aligned backend reasoning still remained visible in important prompt classes
- explicit invocation and attached target files are the preferred reliable use model when specialist behavior matters

### Governance decision

For the current environment, `nodejs-backend-expert` should be treated as an **explicit-invocation-oriented specialist** rather than a delegation-first auto-routed specialist.

## Version 0.2.0: Validation Review Recorded

**Date:** 2026-03-28
**Status:** Recorded

### Findings

- The first routing validation matrix showed that a backend architecture/design prompt did not explicitly trigger `nodejs-backend-expert`
- This was the clearest explicit routing gap in the fleet at that stage
- Later tuning still did not produce reliable explicit delegation for architecture-heavy prompt classes
- Narrow validation also showed domain alignment in some prompt shapes even when explicit delegation did not occur
